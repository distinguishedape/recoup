Running it against your own account

How this drops into a live stack

The engine below the ingest layer knows nothing about Razorpay. Four things change when it moves from this harness to a real merchant.

01

Point a webhook at it

Serve recoup.ingest.webhook_app, register the URL against subscription.pending and payment.failed, and set RAZORPAY_WEBHOOK_SECRET. Signatures are verified against the raw bytes before the body is parsed.

02

Hand it a sink

create_app(config, audit, sink=...). The sink is what runs classify, plan, gate and execute on each event. Without it the receiver only writes to the audit log — which is exactly what the demo build does today.

03

Swap the rail

Recovery outcomes come from SimulatedRail. Replace it with your own charge and messaging transport. RazorpayTestRail.charge() deliberately raises rather than return a plausible number, so nothing simulated can enter through a path labelled real.

04

Set your own limits

Contact window, minimum gap, per-cause budgets and the template allowlist are constants in recoup/policy/rules.py and recoup/plan/budgets.py. Nothing downstream can bypass them: an action is only executable as an AuthorizedAction, and that type can only be constructed inside the policy engine.
